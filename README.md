# تسجيل المندوبين

تطبيق Node.js لتسجيل الطلبات والصور وعرضها في لوحة إدارة محمية. يستخدم SQLite محليًا وSupabase Postgres مع مساحة ملفات خاصة في الإنتاج.

## تشغيل محلي

يتطلب Node.js 24.15 أو أحدث، وحتى الإصدار 26. خدمة Render تستخدم الإصدار المثبت في `.node-version`.

```sh
npm ci
ADMIN_PASSWORD='your-password' npm start
```

افتح `http://localhost:3000/` للتسجيل و`http://localhost:3000/dashboard.html` للإدارة. تحفظ البيانات محليًا في `data/applications.sqlite` ولا ترفع إلى GitHub. كلمة مرور الإدارة ليست جزءًا من الكود.

## إعداد Supabase المجاني

1. أنشئ مشروع Supabase. من SQL Editor نفذ [schema.sql](supabase/schema.sql) لإنشاء الجدولين والحاوية الخاصة `driver-documents`.
2. من Project Settings > API خذ Project URL ومفتاح `service_role` السري. لا تستخدم المفتاح العام، ولا تضع المفتاح السري في GitHub أو الواجهة.
3. الحاوية خاصة ولا توجد سياسات تسمح بالقراءة العامة. تعرض الصور فقط من API بعد دخول الإدارة.

## نشر Render المجاني

أنشئ Render Blueprint من فرع `backend-deploy` للمستودع. يستخدم [render.yaml](render.yaml) خطة `free` بلا قرص دائم. أدخل متغيرات البيئة السرية في Render:

| المتغير | القيمة |
| --- | --- |
| `ADMIN_PASSWORD` | كلمة مرور الإدارة |
| `SUPABASE_URL` | عنوان مشروع Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | مفتاح service_role السري |

يستخدم الإنتاج Supabase تلقائيًا ويفشل بدء التشغيل إن نقصت الإعدادات. بعد النشر افتح رابط `*.onrender.com` للتسجيل و`/dashboard.html` للإدارة. لا تستخدم رابط GitHub Pages القديم حتى يُحوَّل بعد التحقق من الخدمة الجديدة.

## الحدود والنسخ الاحتياطي

الحد الأقصى 4 ميجابايت لكل مرفق. Render المجاني قد يتأخر عند أول زيارة بعد الخمول؛ القرص المحلي فيه مؤقت، لذا لا تُحفظ بيانات الإنتاج عليه. Supabase المجاني قد يوقف المشروع بعد أسبوع من قلة النشاط، ولا يوفر نسخًا احتياطية تلقائية.

لنسخة يدوية من الطلبات، ادخل لوحة الإدارة واضغط «تصدير CSV» واحتفظ بالملف. نزّل المرفقات من روابطها داخل كل طلب، أو نزّل محتويات الحاوية الخاصة من لوحة Supabase Storage. احفظ النسختين في مكان آمن لأنهما تتضمنان بيانات شخصية. لا تضغط «مسح الكل» قبل التأكد من النسخ.
